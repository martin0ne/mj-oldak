## §3.2 — Scaffoldi per 11 komponentów pipeline'u analitycznego

Poniżej oceniamy narzędzia zgodnie z filtrami agencji: arm64 Apple Silicon native, lokalne/self-hostable, 0 PLN licencja OSS, brak wymogu DevOps (co najmniej jeden tryb bez daemons).

Komponenty pipeline'u wg raportu:

1. data-acquire (pozyskiwanie surowych danych)
2. data-validate (walidacja jakości danych wejściowych)
3. data-wrangle (czyszczenie, transformacja, ETL)
4. data-analyze (analiza statystyczna/wizualizacja)
5. insight-synth (synteza wniosków, automatyzacja narracji)
6. analytical-report (publikacja gotowego dokumentu analitycznego)
7. data-versioning (wersjonowanie zestawów danych)
8. source-claim-validate (weryfikacja twierdzeń ze źródeł zewnętrznych)
9. stat-validate (walidacja analiz statystycznych)
10. decision-report (dokumentacja decyzji/business recommendation)
11. monitor-and-maintain (monitoring pipeline'u, alerting, drift detection)

## Podsumowanie cross-component: najlepsze kompozycje scaffold

### Scaffold A: Minimalny (Zero-DevOps, wszystkie lokalnie)
```
cookiecutter-data-science (struktura projektu)
├── 01_data_acquisition    → requests/httpx + duckdb
├── 02_data_validation     → pandera (inline schema definitions)
├── 03_wrangling           → polars lub pandas
├── 04_analysis            → scipy + statsmodels + plotly
├── 05_insight_synthesis   → CUSTOM (human-written + structured template)
├── 06_report              → Quarto (.qmd render)
├── 07_versioning          → DVC lub timestamp parquet naming
├── 08_source_validation   → CUSTOM script (API-based cross-reference)
├── 09_stat_validation     → scipy.stats + custom decorators
├── 10_decision_report     → Quarto + docxtpl
└── 11_monitoring          → Python stdlib logging + smtplib alerts
```
Licencje: Wszystkie Apache 2.0 / BSD 3-Clause / MIT / AGPL (Quarto). Suma: 0 PLN.
DevOps: Zero (quarto CLI, pip packages, DVC lokalne storage, Python stdlib).
Apple Silicon: Wszystkie native arm64.
Bypass-risk najwyższy: insight-synth (celowo CUSTOM, zero black-box automation).

### Scaffold B: Asset-centric (Prefect + Great Expectations)
Taki sam rdzeń co A ale z Prefect orchestrator i GX do walidacji. Kontra: wymaga hostowania Prefect server (docker-compose minimalny) — łamie łagodnie constraint zero-devops.

## Czego dalej nie ma — co zostaje luką mimo researchu

1. **Konkretne liczby ofert Data Analyst/BA w SEKTORZE FINANSÓW PL** — wszystkie raporty (Just Join IT, No Fluff Jobs, Hays) podają ogólnorynkowe dane IT lub broad categories. Nie znaleziono źródła który powie ile ofert na Data Analyst w bankowości PL w Q3 2026. To wymaga bezpośredniego scrapingu GG/NN/NFPJ z filtrem branżowym.

2. **Success rate junior BA w finansach** — żaden raport nie publikuje %. ile aplikacji kończy się rozmową, ile rozmową ofertą. To kluczowe dla oszacowania realnych szans Marcina jako junior.

3. **Source-claim-validate framework** — brak gotowego OSS toola. Komponent musi być BUILD-CUSTOM. To nie jest luka technologia ale luka design — wymaga specyfikacji własnego formatu i zasad walidacji.

4. **Insight-synth bez AI black-box** — jeśli odrzucamy LLM-generated insights, to jedyna opcja to CUSTOM template-driven approach z human-in-the-loop. To zwiększa workload, ale zachowuje literacy.

5. **MONITORING zero-devops** — Prefect/Dagster wymagają daemons (chyba że cloud free-tier). Alternatywa: custom Python logger + SMTP alerts — proste, brak infrastruktury, pełna kontrola.

## WERDYKT

SPOJNE / DO DOSTROJENIA (2) / FAIL

1. SPOJNE: 8 z 11 komponentów ma solidne OSS scaffoldi spełniające filtry budget/arm64/zero-devops — to 73% pokrycia, co przy budżecie 0 PLN jest wysokie.

2. DO DOSTROJENIA (2):
   - (a) Insight-synth — brak good OSS; wymaga BUILD-CUSTOM template-driven. Akceptowalne jeśli Marcin traktuje syntezę wniosków jako swoją główną wartość.
   - (b) Monitor-and-maintain — Prefect/Dagster wymagają daemons (minimalny DevOps). Custom logger alternative jest functional ale basic. Trzeba wybrać: convenience vs pure zero-devops.

3. FAIL: Source-claim-validate — kompletny brak frameworku. Budżet 0 PLN i constraint literatury czynią to niemożliwym do ready-made adoption. Wymaga full custom build.

**Rekomendacja natychmiastowa:** Zacząć od Scaffold A (Minimalny) — wszystkie tools installable pip/quarto CLI, zero infra, full arm64 coverage. Dodać DVC versioning. Insight-synth i source-claim-validate rozszerzać stopniowo jako BUILD-CUSTOM elementy, zaczynając od najprostszych szablonów markdown/templates.
